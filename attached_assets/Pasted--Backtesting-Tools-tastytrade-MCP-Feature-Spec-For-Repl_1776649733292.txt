# Backtesting Tools — tastytrade MCP Feature Spec

**For:** Replit / developer implementing new tools in `tastytrade-mcp`  
**Goal:** Add backtesting capabilities so an AI trading assistant can validate strategies before entering live trades, directly closing the loop between signal generation and historical evidence.

---

## Why This Matters

The MCP already handles live data and order execution. The missing layer is **evidence** — the ability to answer *"has this VRP trade actually made money?"* and *"under what conditions?"* before sizing into a position. Backtesting is the quantitative foundation that separates disciplined vol selling from guesswork.

tastytrade already provides a backtesting REST API at `backtester.vast.tastyworks.com` — we just need to expose it through the MCP.

---

## API Reference

**Base URL:** `https://backtester.vast.tastyworks.com`  
**Auth:** Same session token used for all other tastytrade API calls (already available in the MCP client).

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/available-dates` | Which symbols have historical data and for what date range |
| `POST` | `/backtests` | Submit a backtest job |
| `GET` | `/backtests/{id}` | Poll status; get results when complete |
| `POST` | `/backtests/{id}/cancel` | Cancel a running job |
| `POST` | `/simulate-trade` | Lightweight single-trade historical price lookup (no entry/exit logic) |

---

## Tools to Add

### 1. `get_available_backtest_dates`
Check which symbols are available for backtesting and their date ranges.

**Parameters:** none (or optional `symbol` filter)  
**Returns:** `[{ symbol, earliestDate, latestDate }]`

---

### 2. `run_backtest`
Submit a multi-leg options strategy backtest and return the job ID.

**Parameters:**

```ts
{
  symbol: string,                  // e.g. "SPY", "QQQ", "TLT"
  startDate: string,               // "YYYY-MM-DD"
  endDate: string,                 // "YYYY-MM-DD"
  legs: Leg[],                     // 1–4 legs (see Leg schema below)
  entryConditions: EntryConditions,
  exitConditions: ExitConditions
}
```

**Leg schema:**
```ts
{
  type: "equity-option",
  direction: "long" | "short",
  side: "call" | "put",
  quantity: number,                // 1–10
  daysUntilExpiration: number,     // DTE at entry (e.g. 30, 45)
  strikeSelection: "delta" | "percentageOTM" | "premium",
  delta?: number,                  // 1–100 when strikeSelection = "delta"
  percentageOTM?: number,          // e.g. 0.10 = 10% OTM
  premium?: number                 // target credit
}
```

**EntryConditions schema:**
```ts
{
  frequency: "every day" | "on specific days of the week",
  specificDays?: number[],         // [1,3,5] = Mon/Wed/Fri
  maximumActiveTrials?: number,    // max concurrent positions
  maximumActiveTrialsBehavior?: "don't enter" | "close oldest",
  minimumVIX?: number,
  maximumVIX?: number
}
```

**ExitConditions schema:**
```ts
{
  takeProfitPercentage?: number,   // e.g. 50 = close at 50% of max profit
  stopLossPercentage?: number,     // e.g. 200 = stop at 2x credit received
  atDaysToExpiration?: number,     // close at X DTE
  afterDaysInTrade?: number
}
```

**Returns:** `{ backtestId: string, status: "pending" | "running" }`

---

### 3. `get_backtest_results`
Poll a submitted backtest for status and results.

**Parameters:** `{ backtestId: string }`

**Returns (when complete):**
```ts
{
  status: "completed" | "running" | "pending",
  progress: number,               // 0–100
  statistics: {
    totalTrades: number,
    winRate: number,
    averageProfitLoss: number,
    totalProfitLoss: number,
    maxDrawdown: number,
    sharpeRatio?: number
  },
  trials: {
    openDateTime: string,
    closeDateTime: string,
    profitLoss: number
  }[],
  snapshots: {
    dateTime: string,
    cumulativeProfitLoss: number,
    underlyingPrice: number
  }[]
}
```

---

### 4. `simulate_trade`
One-shot: look up historical prices for a specific option structure. Useful for quickly answering "what would I have paid/received on date X?" without a full backtest job.

**Parameters:**
```ts
{
  underlying: string,
  startTime?: string,              // ISO datetime
  endTime?: string,
  legs: { symbol: string }[]      // OCC-format option symbols
}
```

**Returns:** Per-date pricing: `{ dateTime, price, effect, underlyingPrice, delta }[]`

---

## Implementation Notes for the Developer

1. **Auth:** Use the same `getClient()` session token already wired in `tastytrade-client.ts`. The backtesting API base URL is different — add a constant `BACKTEST_BASE_URL = "https://backtester.vast.tastyworks.com"` and make raw `fetch` calls with `Authorization: Bearer <session-token>`.

2. **File placement:** Add a new file `src/tools/backtest-tools.ts` following the same pattern as `market-data-tools.ts`. Register in `tool-registry.ts`.

3. **Async pattern:** `run_backtest` submits and returns immediately with a job ID. `get_backtest_results` is the polling tool — the AI will call it until `status === "completed"`. Do NOT block in `run_backtest` waiting for completion (backtests can take 30–120 seconds).

4. **Error handling:** Use the existing `error-utils.ts` pattern. If the backtest API returns 401, surface a clear message that the session may need refresh.

5. **Response size:** `trials` arrays can be large (1000+ trades over multi-year backtests). Return them in full — the AI skill layer will summarize. Do not truncate.

---

## Priority Order

| Tool | Priority | Notes |
|---|---|---|
| `run_backtest` | P0 | Core capability |
| `get_backtest_results` | P0 | Required to read results |
| `get_available_backtest_dates` | P1 | Helps scope valid date ranges |
| `simulate_trade` | P2 | Nice-to-have for quick spot checks |

## Example Backtest Configurations (for testing)

**VRP Core — SPY 45 DTE short strangle, 16Δ, 50% profit target:**
```json
{
  "symbol": "SPY",
  "startDate": "2020-01-01",
  "endDate": "2025-12-31",
  "legs": [
    { "type": "equity-option", "direction": "short", "side": "put", "quantity": 1, "daysUntilExpiration": 45, "strikeSelection": "delta", "delta": 16 },
    { "type": "equity-option", "direction": "short", "side": "call", "quantity": 1, "daysUntilExpiration": 45, "strikeSelection": "delta", "delta": 16 }
  ],
  "entryConditions": { "frequency": "every day", "maximumActiveTrials": 1 },
  "exitConditions": { "takeProfitPercentage": 50, "stopLossPercentage": 200, "atDaysToExpiration": 21 }
}
```

**VRP High-IV Gate — same as above but only enter when VIX ≥ 18:**
```json
{
  "entryConditions": { "frequency": "every day", "maximumActiveTrials": 1, "minimumVIX": 18 },
  "exitConditions": { "takeProfitPercentage": 50, "atDaysToExpiration": 21 }
}
```

Use these as smoke tests during development to confirm results are reasonable (the gated version should show higher win rate and better risk-adjusted returns).

## Acceptance Criteria

- [ ] `run_backtest` submits a job and returns a job ID within 5 seconds
- [ ] `get_backtest_results` returns `status`, `statistics`, `trials`, and `snapshots` when complete
- [ ] Both tools appear in the MCP tool list and are callable from Claude
- [ ] Auth errors surface a helpful message (not a raw 401)
- [ ] The SPY strangle smoke test returns a completed result with >100 trials over a 5-year window
