## Background — What the Backtesting API Supports

**Base URL:** `https://backtester.vast.tastyworks.com`  
**Auth:** Same session token already used in the MCP client.

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/available-dates` | Symbols with available historical date ranges |
| POST | `/backtests` | Submit a backtest job |
| GET | `/backtests/{id}` | Poll status; get results when complete |
| POST | `/backtests/{id}/cancel` | Cancel a running job |
| POST | `/simulate-trade` | Historical price lookup for a specific structure (no entry/exit logic) |

### Strike Selection Methods

The `strikeSelection` field on each leg accepts one of seven methods:

| Method | What it does | Best use |
|---|---|---|
| `delta` | Target a specific delta at entry (1–100) | VRP strangles, 0DTE condors |
| `percentageOTM` | Strike X% away from spot | Earnings crush, momentum skew |
| `percentageOTMRelative` | Strike X% away from *another leg's strike* | Iron condor wings, defined-risk spreads |
| `currentPriceOffset` | Strike at spot ± a fixed dollar amount | Defined-wing condors on high-priced underlyings |
| `currentPriceOffsetRelative` | Dollar offset relative to another leg | Spread width control (e.g. "5 points wide") |
| `currentPriceExactOffsetRelative` | Exact dollar offset relative to another leg | Precise ATM calendars, butterflies |
| `premium` | Select strike matching a target credit | Premium-first sizing (e.g. "sell the $2.00 put") |

**Key field:** `strikeRelativeLeg` — zero-indexed integer pointing to another leg. Required for all relative strike methods. Sign convention: negative = put side (below reference), positive = call side (above reference).

### EntryConditions
```ts
{
  frequency: "every day" | "on specific days of the week" | "on exact days to expiration match",
  specificDays?: number[],               // e.g. [1,3,5] = Mon/Wed/Fri
  maximumActiveTrials?: number,
  maximumActiveTrialsBehavior?: "don't enter" | "close oldest",
  minimumVIX?: number,
  maximumVIX?: number
}
```

### ExitConditions
```ts
{
  takeProfitPercentage?: number,         // % of max profit
  stopLossPercentage?: number,           // % of credit received
  atDaysToExpiration?: number,
  afterDaysInTrade?: number,
  minimumVIX?: number
}
```

## Tools to Add (tastytrade-mcp / src/tools/backtest-tools.ts)

### 1. `run_backtest`
Submit a multi-leg backtest. Returns immediately with a job ID — do NOT block waiting for completion.

**Parameters:**
```ts
{
  symbol: string,
  startDate: string,                     // "YYYY-MM-DD"
  endDate: string,
  legs: Leg[],
  entryConditions: EntryConditions,
  exitConditions: ExitConditions
}
```

**Returns:** `{ backtestId: string, status: "pending" | "running" }`

---

### 2. `get_backtest_results`
Poll a submitted backtest. The AI calls this repeatedly until `status === "completed"`.

**Parameters:** `{ backtestId: string }`

**Returns:**
```ts
{
  status: "completed" | "running" | "pending",
  progress: number,
  statistics: {
    totalTrades: number,
    winRate: number,
    averageProfitLoss: number,
    totalProfitLoss: number,
    maxDrawdown: number,
    sharpeRatio?: number
  },
  trials: {
    openDateTime: string,
    closeDateTime: string,
    profitLoss: number
  }[],
  snapshots: {
    dateTime: string,
    cumulativeProfitLoss: number,
    underlyingPrice: number
  }[]
}
```

> Return `trials[]` in full — do not truncate. The AI skill layer summarizes.

---

### 3. `get_available_backtest_dates`
**Parameters:** none (optional symbol filter)  
**Returns:** `[{ symbol, earliestDate, latestDate }]`

---

### 4. `simulate_trade`
Historical price lookup for a specific option structure at specific dates. Core engine for S&D zone validation and post-trade analysis.

**Parameters:**
```ts
{
  underlying: string,
  startTime?: string,                    // ISO datetime
  endTime?: string,
  legs: { symbol: string }[]            // OCC-format option symbols
}
```

**Returns:** `{ dateTime, price, effect, underlyingPrice, delta }[]` per date

---

### 5. `analyze_earnings_backtest` *(P1 — post-processing wrapper)*
Combines `get_historical_earnings` + `get_backtest_results` + filtering into one call. Enables the Pre-Earnings Expansion strategy to be fully backtested.

**Parameters:**
```ts
{
  symbol: string,
  backtestId: string,
  daysBeforeMin?: number,               // default 10
  daysBeforeMax?: number,               // default 21
  earningsLimit?: number                // default 20
}
```

**Internally:**
1. `get_historical_earnings(symbol, limit)` → earningsDates[]
2. `get_backtest_results(backtestId)` → trials[]
3. Filter: keep trials where `openDateTime` falls [daysBeforeMin, daysBeforeMax] days before any earnings date
4. Return filtered stats vs. unfiltered baseline side-by-side

**Returns:**
```ts
{
  filteredStats: { trialCount, winRate, avgPnL, totalPnL, expectancy },
  baselineStats: { trialCount, winRate, avgPnL, totalPnL, expectancy },
  earningsDatesUsed: string[],
  matchedTrials: { openDateTime, closeDateTime, profitLoss, daysBeforeEarnings }[]
}
```

---

### 6. `analyze_zone_backtest` *(P2 — candle + simulate-trade loop)*
Validates a Supply & Demand zone by finding every historical price touch via candles, then running `simulate-trade` for each touch window and aggregating P&L.

**Parameters:**
```ts
{
  symbol: string,
  zonePrice: number,
  zoneTolerance?: number,               // default 0.005 (±0.5%)
  direction: "long" | "short",
  legs: { symbol: string }[],           // OCC symbols, or empty for equity
  lookbackDays?: number,                // default 504
  holdingPeriodDays?: number
}
```

**Internally:**
1. `get_candles(symbol, periodMinutes=1440, daysBack=lookbackDays)` → OHLCV
2. Find candles where price entered the zone band → touch dates
3. `simulate-trade` for each touch (startTime=touch, endTime=touch+holdingPeriod)
4. Aggregate across all touches

**Returns:**
```ts
{
  zonePrice: number,
  touchCount: number,
  winRate: number,
  avgPnL: number,
  expectancy: number,
  touches: { date, entryPrice, exitPrice, profitLoss, won }[]
}
```

## Implementation Notes

- **Auth:** Use existing `getClient()` session token. Add `BACKTEST_BASE_URL = "https://backtester.vast.tastyworks.com"` and make raw `fetch` calls with `Authorization: Bearer <token>`.
- **File:** `src/tools/backtest-tools.ts` — register in `tool-registry.ts`
- **Async:** `run_backtest` returns immediately. Never block waiting for completion.
- **`strikeRelativeLeg` is zero-indexed.** Pass incorrectly and relative strikes will be wrong.
- **`currentPriceExactOffsetRelative: 0`** pins a leg to the exact same strike as the reference — correct way to build ATM calendars.

|---|---|---|---|

| **Earnings Volatility Crush** | ✅ Full | `run_backtest` + earnings date mask | filtered trials |
| **Forward Factor** (calendar) | ✅ Full | `run_backtest` direct | backtester trials |
| **Momentum Skew** (debit spread) | ✅ Good | `run_backtest` on trending names | backtester trials |
| **Pre-Earnings Expansion** (long straddle) | ✅ Full | `run_backtest` + `analyze_earnings_backtest` | filtered trials |
| **Supply & Demand Zones** | ✅ Good | `get_candles` → zone touches → `analyze_zone_backtest` | aggregated simulate-trade P&L |
