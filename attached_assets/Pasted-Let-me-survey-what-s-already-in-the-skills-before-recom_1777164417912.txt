### Per-File Change Recommendations

**1. `trading-strategies/references/vrp.md`** — add a "Hard Rules (Account-Size Gated)" section near the top:

> ### Hard Rules
> - Net liq < $50k → defined-risk only (Iron Condor or Long Butterfly). **No uncovered strangles.**
> - Every entry must be an OTOCO (entry + OCO bracket exit). Profit target = 50% credit, stop = 2× credit. Single-leg entry without bracket is forbidden.
> - 21-DTE time stop is mechanical, not optional. Set GTC close order at entry dated to 21-DTE.
> - Single-name cost basis cap = 25% of net liq across all positions in that underlying. New entry that would breach the cap requires closing existing exposure first.

**2. `trading-strategies/references/forward-factor.md`** — strengthen Stage 2 from "should" to "must":

> ### Stage 2 is a Hard Gate (not a recommendation)
> Stage 1 (term-structure FF from hook) is necessary but **never sufficient**. No entry without a Stage 2 strike-level scan returning a positive FF_strike. If `get_options_greeks` is unavailable mid-session, **skip the trade** — do not enter on Stage 1 alone.
>
> ### Concurrent FF Cap
> Maximum 1 active calendar per underlying. Layered diagonals (e.g. USO 120 May/Jun + USO 130 Jun/Jul simultaneously) are forbidden — they're the same FF bet at different strikes, doubling concentration without adding edge.

**3. `trading-strategies/references/earnings-crush.md`** — set calendar as default below $50k:

> ### Account-Size Default
> - Net liq < $50k → **calendar only**. The 28% std dev (vs 48% for short straddle) is essential at small account sizes where one tail event = double-digit drawdown.
> - Net liq ≥ $50k → either structure if the diversification rule is met (≥10 concurrent earnings trades per cycle).

**4. `trading-strategies` main skill** — add a new top-level section "Portfolio Construction" before "The Seven Strategies":

> ### Portfolio Construction
>
> **Diversification target:** at any time, run ≥3 concurrent strategies (4+ preferred), with no single strategy > 40% of deployed capital. A single-strategy book has higher correlation in regime shifts.
>
> **Pre-trade plan or no entry:** before any order leaves the dry-run stage, write down: (a) thesis in one sentence, (b) profit target, (c) stop loss, (d) time stop, (e) invalidation condition. If any of the five can't be filled in, do not enter.
>
> **Tiered acceleration sequence:** when an account is underperforming its growth plan, address in this order — (1) process discipline (OCO enforcement, plans, position cap), (2) strategy diversification (add idle strategies), (3) capital injection (deposits at small-account stage are highest-IRR), (4) sizing increases (only after 1–3 are running cleanly).

### Hook Recommendations (text alone won't enforce)

The skills are advisory — only hooks block. Three new PreToolUse hooks to install in `~/.claude/hooks/`:

**A. `tt-require-bracket.py`** — fires on `create_order` and `create_complex_order`:
- If the order is a short-premium open (any leg with `Sell to Open` on options, no offsetting `Buy to Open` of equal-or-greater debit) → check the order JSON includes OTOCO wrapper. If not, **block** with message "Short premium open requires OTOCO bracket. Add profit (50% credit) and stop (2× credit) legs."

**B. `tt-concentration-cap.py`** — fires on `create_complex_order`:
- Read `/tmp/tt_netliq.json` for current net liq.
- Sum existing positions cost basis by underlying.
- If new order would push that underlying > 25% of net liq → **block** with message "Concentration cap: USO already at 147% of net liq. Close one existing leg before adding."

**C. `tt-require-plan.py`** — fires on `create_order` / `create_complex_order`:
- Check `/tmp/tt_pending_plan.json` for a plan with thesis/profit/stop/time/invalidation filled.
- If missing or stale (> 60 min) → **block** with "No pre-trade plan. Write one to /tmp/tt_pending_plan.json before submitting."

You already have `tt-require-dry-run.sh` — same pattern.
